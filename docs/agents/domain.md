# Domain documentation

Mixcat uses a single domain context for the desktop workbench, native Codex sessions and workflow orchestration.

- Read the relevant documents indexed by [docs/design/README.md](../design/README.md) before changing their behavior. Architecture, functionality and other design documents belong under `docs/design/`; archived prototypes belong under `prototypes/`.
- Read the root `GLOSSARY.md` and relevant existing architecture decision records if present. Missing glossary or ADR files do not block work and do not require empty scaffolding.
- Use the established domain vocabulary and flag conflicts with existing design decisions instead of silently changing them.
- Keep confirmed user requirements, implemented behavior and proposed changes distinct. Use current code and runtime evidence to assess implementation status.
- This file configures engineering skills; it does not change native node capabilities, plugin selections, MCP tools, workflow routes or human-review decisions.
