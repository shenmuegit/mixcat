# Mixcat 文档目录

架构设计、功能设计和其他专项设计统一存放在 [设计文档目录](design/README.md)（`docs/design/`）。原型不收录，实施计划与执行记录单独放在 `docs/plans/`。

**从 [客户端功能设计](design/2026-10-19-mixcat-client-functional-design.md) 开始。** 这是正式产品目标的统一入口。当前客户端仅为验证原型；文档分别记录已确认行为、原型观察、历史实验和待实施要求，不能将原型测试当成正式架构已验收。本次仅修订文档，新增或调整功能时先更新设计，再另行决定实施范围。

## 当前设计与使用入口

| 文档 | 用途 |
| --- | --- |
| [客户端功能设计](design/2026-10-19-mixcat-client-functional-design.md) | 目标行为、功能清单、原型观察与正式验收要求 |
| [架构可靠性与边界修订](design/2026-10-20-architecture-hardening.md) | 七项审计问题的设计修订、待实施验收及有限权限实验；不表示已修复正式产品 |
| [会话工作台专项设计](design/2026-10-19-session-workbench-design.md) | 右键创建、模型与能力选择、条件边、自由会话、历史和工作面板 |
| [节点状态与暂停覆盖](design/2026-10-19-node-controls.md) | 每节点唯一状态、四种控制覆盖、恢复范围与中断竞态 |
| [项目 README](../README.md) | 安装启动、实际操作、运行边界、数据位置和验证命令 |

节点能力选择只增加或激活能力，不限制 Codex 原生能力。普通输入输出自由，节点 cwd 是所属项目目录；旧模板和 MCP 兼容契约不推广为所有消息的固定格式。原型已有条件保存编辑及网页文件预览，条件 MCP 选择规范、Agent 浏览器控制和 MCP App UI 双向桥仍须分别设计或实施。原生能力接入目标不等于原型已保留所有官方宿主功能。

“全部暂停/开启”当前指选定项目内的全部节点。每个节点各自拥有一份多值 `status`，四种操作直接覆盖它；项目汇总状态和暂停时运行名单不构成额外控制锁。空闲节点恢复待命，之后可正常接收新交接。

## 目录分工

| 目录 | 内容 |
| --- | --- |
| `docs/design/` | 架构、功能和专项设计，不放原型。 |
| `docs/plans/` | 历史实施计划与执行记录，不作为另一套产品需求。 |
| `prototypes/desktop/` | 归档客户端源码、测试和启动配置，供后续设计参考与验证。 |
| `prototypes/ui/` | 静态界面图与渲染源，包括极简和像素风方向。 |
| 现有项目 `.runtime/` 与项目内 `.mixcat/` | 既有运行证据、真实项目数据、会话与登录材料；不随原型源码归档搬迁或清理。 |
