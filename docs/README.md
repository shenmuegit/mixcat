节点能力选择只增加或激活能力，不限制 Codex 原生能力。普通输入输出自由，节点 cwd 是所属项目目录；旧模板和 MCP 兼容契约不推广为所有消息的固定格式。条件保存编辑及网页文件预览已有正式实现；MCP 的五个核心工具已完成实施，通过节点目录和自然语言条件指导选路，允许向无连线节点发送并记录理由。Web 产品团队模板已用六个真实原生会话完成极小产品开发、回流和验收；用户批准测试项目的具体定义后，七类 planning-with-files 原生 hooks 与多会话计划隔离也已实测。外部浏览器 MCP 调用已有本机证据，面板中的 Agent 浏览器控制桥和 MCP App UI 双向桥仍单独设计或实施，网页预览不代表已保留所有官方宿主功能。

“全部暂停/开启”当前指选定项目内的全部节点。每个节点各自拥有一份多值 `status`，四种操作直接覆盖它；项目汇总状态和暂停时运行名单不构成额外控制锁。空闲节点恢复待命，之后可正常接收新交接。

## 目录分工

| 目录 | 内容 |
| --- | --- |
| `docs/design/` | 架构、功能和专项设计，不放原型。 |
| `docs/plans/` | 历史实施计划与执行记录，不作为另一套产品需求。 |
| `prototypes/desktop/` | 归档客户端源码、测试和启动配置，供后续设计参考与验证。 |
| `prototypes/ui/` | 静态界面图与渲染源，包括极简和像素风方向。 |
| 现有项目 `.runtime/` 与项目内 `.mixcat/` | 既有运行证据、真实项目数据、会话与登录材料；不随原型源码归档搬迁或清理。 |
