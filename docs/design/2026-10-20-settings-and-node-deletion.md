# 客户端设置、共享 Codex 账号与节点删除

日期：2026-10-20。状态：已确认并实现；验证记录见本文末尾。本文覆盖此前按项目登录的实现，项目工作目录、独立会话和四种运行控制继续遵循客户端功能设计。

## 已确认的交互

最左侧窄栏的左下角提供“设置”齿轮按钮，悬停显示名称，打开设置后显示选中状态；不在项目／笔记／知识库菜单中重复放置入口。账号设置仅保留“Codex 账号”标题和一个“登录 Codex”按钮，点击后自动建立原生连接并打开登录流程，不要求先连接；失败后可再次点击重试，已登录时按钮显示“已登录”。不展示连接状态、账号详情、原生版本和说明文字；仅在失败时展示错误。没有项目时也能登录，整个客户端共用此账号。进入设置后，当前项目标签仍保留，点击标签可返回工作流。

打开认证网页不视为登录成功；原生账号查询确认认证且共享凭据可用后，按钮显示绿色勾和“已登录”，不再允许重复点击。账号变更通知会使较早的查询结果失效，旧的未登录结果或错误不能覆盖新的登录状态。桌面后台启动后异步检查本客户端保存的登录；有缓存时恢复账号状态，不打开浏览器或启动项目任务，无缓存时保持待登录，仍由用户点击登录触发连接。

节点右键菜单和节点详情提供“删除节点”。确认框说明：从画布移除节点及其配置关联边，保留会话历史、任务、交接记录、成果和项目文件。取消不会提交删除。节点有运行、暂停、排队、等待来源确认、状态待核对的任务或原生请求待回应时，禁止删除并说明先处理任务。暂停本身不代表任务已经完成。

按用户截图精简界面：项目卡片移除执行模式与日期；节点详情移除顶部连接栏、英文栏目标题和重复工作目录；状态概览移除批量恢复数量说明；消息区移除执行模式选择器，消息仍使用项目既有执行模式；画布移除操作说明，侧栏与页脚左侧移除本地空间提示。项目栏的目录、节点状态和操作控件继续展示，卡片“进入工作流”与页脚右侧文字保持靠右对齐。

项目历史继续展示已移除节点的内容、名称与输入来源，标记“已移除”。原生历史可按保存的 thread 继续读取，不能从历史重新启动已删除的节点。全部节点移除后，仍可查看历史和添加新节点。历史资源可以在现有节点的工作面板打开；没有现有节点时，提示先添加节点，原文件与历史继续保留。

## 账号与数据归属

| 对象 | 所属位置与职责 |
| --- | --- |
| 客户端账号连接 | 工作台根目录 `.runtime/client/account/` 为独立 Codex home，负责原生 OAuth 登录、凭据持久化与刷新；不在这里执行项目任务。 |
| 项目原生连接 | 每项目 `.mixcat/codex/` 保留独立 Codex home、会话文件与运行数据；原生 cwd 和 thread cwd 均为所属项目。 |
| 项目认证 | 后台从账号连接自己的原生凭据中提取 access token、账号 ID 与套餐，经原生 external-token 登录注入项目连接内存；不转发 refresh token，不复制全局会话目录。 |
| 界面状态 | `AppSnapshot.account` 单独表示全客户端账号；`runtime` 继续表示当前项目连接。全量与增量更新均携带账号状态，界面不接收 token。 |

所有路径仍校验真实祖先和目录边界，不使用目录联接共享 home，也不读取官方客户端或宿主的登录凭据。旧项目已有登录文件原位保留；新的共享账号需要在设置中登录，不自动选择某个旧项目账号作为全局账号。

账号原生连接与项目连接均共享并发初始化、保留关闭中的客户端所有权，并拒绝关闭后的迟到回调。每次原生轮次派发前重新核对共享账号，包括暂停恢复和排队任务。账号请求失败不能自动重发项目任务。设置中的新登录会拒绝与正在执行的原生任务交错；已暂停或排队任务在后续派发前重新绑定当前账号。

项目收到 `account/chatgptAuthTokens/refresh` 时，统一向账号连接请求原生刷新。并发刷新合并；响应前核对项目连接、请求是否仍待处理及先前账号 ID。原生撤销请求或投递已过期时就地结束，不向旧请求重复回应，不把投递失效当作账号失效。

### 原生兼容性边界

当前接入使用 `account/login/start` 的 `chatgptAuthTokens` 分支和 `account/chatgptAuthTokens/refresh`。实际安装版本 `0.163.0-alpha.10.2` 的生成 schema 将 external-token 登录标记为内部、不稳定接口；这不是跨版本支持承诺。实际合成 token 探测已确认该版本接受此登录，且不会在项目 home 创建 `auth.json`，没有执行模型调用。升级 Codex 时必须重新验证协议与凭据格式；不兼容时明确报错，不回退到项目旧账号。

原生文件凭据格式的依据是 [Codex 登录存储源码](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/storage.rs)，协议以安装二进制生成的 schema 为准。真实 OAuth、真实刷新服务、真实模型推理仍需使用用户账号单独验收。当前可信本地 OS 用户的边界不变，不声称对恶意本地代码提供强隔离。

## 删除的数据契约

数据库仍使用既有项目状态事务。删除在候选状态内完成：把完整节点定义和各模式 thread 绑定移入 `archivedNodes`，移除活动节点、入出配置边及该节点的批量恢复标记，记录删除活动；成功保存后才发布状态并撤销节点 MCP 凭据。保存失败时节点、关联边和凭据继续保持原状。

任务、交接、原始输入输出、原生条目和成果不被删除。已删除节点 ID 不可复用，避免新会话混入旧历史。读取历史允许使用归档节点，发送、交接选路、配置和重试仅允许使用活动节点。异步消息与重试在等待后重新检查节点存在；删除抢先完成时，等待中的重试失败，不能改写已保留的旧任务。

宿主观察到活动节点移除后，关闭该节点的网页和文件 `WebContentsView`，清理活动绑定。旧绑定的布局请求不能重新显示已删除节点面板。删除不移除原生会话文件、下载、附件或项目文件，也不提供永久清空历史或撤销删除功能。

## 验证与未验收项

执行回归覆盖：无项目登录入口、两项目共享账号但 home/cwd 独立、refresh token 不外传、快照不含凭据、凭据解析错误不回显内容、暂停恢复重新绑定账号、原生刷新请求撤销、历史与 thread 绑定跨重启保留、ID 禁止复用、未完成任务阻止删除、保存失败保持原状、删除与重试并发。

界面验证分别使用实际 Electron DOM／鼠标／命中测试与受控 IPC，及实际 main／preload／worker／engine／PanelHost 删除链路；合成账号不等于真实登录。证据保存在 `.runtime/implementation/`，索引见[当前交付与验收矩阵](2026-10-20-delivery-status.md)。现阶段未新增退出账号、账号切换器、永久删除历史和自动迁移旧项目账号。
