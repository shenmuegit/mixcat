# 独立 Excalidraw 画布

日期：2026-11-01。关联 [Issue #180](https://github.com/shenmuegit/mixcat/issues/180)。

## 用户已确认的目标

- 画布是 Mixcat 的独立模块，可以用于项目，也可以用于与项目无关的内容。
- 首版 Codex 不参与，优先 1:1 复刻画布。
- 用户对范围的最终描述：不需要协作和分享，完整复刻画布、动效、样式、布局和设计。

本设计按仓库已授权的确认、Issue、实现、验证、审查、PR、合并及客户端重启流程交付。实现选择由 Agent 负责核实；不把技术选择写成用户逐项指定。

## 实现路线与依据

采用官方 React 编辑器。2026-11-01 实际打开官网，页面资产 `index-DVAv9QEc.js` 声明 `VITE_APP_GIT_SHA=4ce8305ca78e4ea05ad78c306292932bfe6b256f`；官方 npm 的对应版本为 `@excalidraw/excalidraw@0.18.0-4ce8305`。固定完整版本和 lockfile，不使用浮动 next。该版本包含官网当前的便签等工具。

| 方案 | 对目标的影响 | 选择 |
| --- | --- | --- |
| 嵌入与官网提交匹配的官方编辑器 | 直接继承工具、样式、动效及布局；补齐桌面保存和入口 | 采用，Agent 的实现选择 |
| 自行绘制一套相似编辑器 | 需要重做选择、几何、文字、快捷键及大量细节，难以达到 1:1 | 不采用 |
| 嵌入公网网站 | 桌面持久化和版本受外站控制，附带本轮不需要的云服务入口 | 不采用 |

参考：[官方集成](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/integration)、[场景 API](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props/excalidraw-api)、[自托管字体](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/installation)。

## 界面和交互

最左侧功能栏增加“画布”，现有侧栏随模块展示画布列表和新建入口。主编辑区域由官方编辑器占满；不增加挡住画面的自定义工具条。列表可以新建、选择、重命名和删除画布，删除前显示明确确认。

编辑区域直接使用官方工具栏、左上菜单、形状属性面板、素材库、底部缩放/撤销/重做/帮助，以及原生选择、拖动、对齐、绑定箭头、文字、便签、图片、分组、框架和更多工具。保留官方中文、主题切换、提示、快捷键、鼠标光标及过渡动效。官方编辑器的内部布局以它自己的可用矩形为基准，Mixcat 的模块入口和列表是编辑区域之外的宿主导航。

实时协作、在线分享、Excalidraw+ 推广和联网 AI 入口不属于本轮。普通绘图和素材库的本地文件导入导出仍应工作。项目关系不作为创建和使用画布的条件；本轮不增加强制项目选择。

## 持久化与生命周期

每张画布具有稳定 ID、名称、独立修订号、创建/更新时间及场景。场景包含图形、文字、图片数据和可恢复的 appState（含视口和主题）。本地素材库作为画布模块的共享偏好单独保存。

保存通过专用桌面 IPC，使用已有 frame 授权规则和项目路径校验；不扩大普通后台命令的大小上限。存储位于 Mixcat workbench root 的 `.mixcat/canvases/`，与某个业务项目的创建/删除解耦。采用现有 Node SQLite 能力，原子保存、预期修订号检查和请求编号防重放；列表只返回摘要，打开时读取完整场景。

单次场景上限 64 MiB，素材库上限 8 MiB；拒绝不合法操作、身份、修订号、JSON 形状和超限内容。数据库及旁文件拒绝符号链接、目录联接和硬链接。资源和字体随构建本地提供，核心编辑无须公网请求。

renderer 串行保存，区分已经保存的版本和保存期间新增的编辑。切换画布先完成当前保存；失败或冲突留在原画布并保留草稿，显示可重试的错误。迟到响应不能覆盖新画布。模块切换可保持当前画布挂载并完成保存；隐藏编辑器不捕获全局快捷键。退出沿用未保存保护，保存成功后才解除 dirty 状态。

官方文件导入与导出继续使用官方格式。主窗口的下载将目标限制在 `.mixcat/canvases/exports/`，验证文件名及真实路径，防止默认下载写到用户目录。PNG、SVG 和 .excalidraw 必须在实际 Electron 中验证。

## 1:1 的核对标准

对照相同编辑区宽高、DPR、语言、主题和所选工具；分别核对空白、矩形属性、菜单、素材库、颜色选择器、更多工具和有内容的画布。

官网在 1442×1007 CSS px、DPR 1.5、浅色中文下：工具栏位置 x=450/y=16，尺寸 542×44，圆角 8；矩形属性面板 x=16/y=76、宽 195；编辑器 UI 字体为 Assistant 加系统字体；底部控件距底部约 16。相同宽高下应使用官方值，不能被 Mixcat 的全局 button/input/dialog/字体样式覆盖。其他宽度遵循官方响应式布局。

交互验证必须包含实际指针绘制、文字和便签编辑、选中移动、颜色修改、平移缩放、撤销重做、菜单/素材库打开收起、导入导出、窗口缩放和保存后重开。对动效核对原生样式及实际反馈，不以静态截图代替交互结果。

## 验证与交付

测试边界由本设计和仓库授权的交付要求确定：存储公开命令边界验证多画布保存/恢复、冲突/重放、删除和非法输入；renderer 保存协调边界验证编辑中保存、失败重试及切换竞争；真实桌面边界验证官方编辑器渲染、文件互通、隔离和退出恢复。

完成相关测试、typecheck、构建和一次完整测试；Standards 与 Issue/设计验收由两个独立 Agent 并行审查。合并后从最终 main 构建，正常退出并重启正式客户端，记录合并 SHA、进程路径/启动时间和新的 desktop ready，再验收实际入口与画布。

## 实现时必须核实的事项

- 官方构建的资源目录、公开序列化接口、字体及 CSS 的实际形式，由实施阶段读取包内容确认。
- 宿主全局样式污染先通过作用域或独立样式入口解决，避免改写上游绘图逻辑。
- 若当前官方构建暴露 Electron 不支持的文件 API，则在桌面文件边界做最小适配，并记录实际行为和证据。
- 官网以后更新不自动改变已交付版本；升级另行核对版本和视觉/交互回归。
