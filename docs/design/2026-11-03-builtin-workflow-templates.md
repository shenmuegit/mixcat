# 四种内置项目工作流

日期：2026-11-03。Issue：[#191](https://github.com/shenmuegit/mixcat/issues/191)。

用户确认先提供调研分析、内容创作、缺陷修复和 Web 产品团队四种内置模板，其他模板不进入新建选择。

## 目标和方案

减少用户重复配置角色与交接条件的操作。采用现有节点、条件边、原生独立会话和能力目录配置；模板创建后仍可修改。相比自定义模板库或对话生成工作流，增加固定场景模板的范围更小，直接满足本次选择。

新建选择顺序为调研分析、内容创作、缺陷修复、Web 产品团队，默认调研分析。已有基础工作流和 ComfyUI 项目继续按持久化定义重开；创建入口调整不迁移项目、不重写历史。兼容调用仍接受省略模板及 ComfyUI 标识。

## 职责与交接

| 模板 | 角色 | 主路径和回流 |
| --- | --- | --- |
| 调研分析 | 研究协调、资料研究、独立核查、报告汇总 | 协调→研究→核查→汇总→协调；核查发现缺口返回研究，汇总发现证据缺口返回核查，研究范围问题返回协调 |
| 内容创作 | 策划编辑、内容撰写、事实核查 | 编辑→撰写→核查→编辑；核查发现问题返回撰写，撰写遇到方向问题返回编辑 |
| 缺陷修复 | 复现诊断、修复实现、回归验证 | 诊断→修复→验证→诊断；修复发现根因不符返回诊断，验证失败返回修复 |
| Web 产品团队 | 现有八个独立角色及产品定义分组 | 使用当前 Web 模板的完整定义 |

共同约定：先读取项目上下文，用户对话明确当前目标和范围；出边工具显式投递并保留关联回复。交接说明问题、成果、来源或版本、实际验证及待办。正式成果写项目文档，工作记忆按模板自己的计划标识存储；协调者维护总计划。人工问题使用现有提问机制，不新增固定审批。模型继承原生默认，创建和配置不启动模型任务。

调研区分引用事实与推断，记录来源和日期；核查者独立检查关键证据；报告保留分歧与不确定性。创作区分素材授权、事实和表达，保留用户稿件与修改依据；编辑负责目标和成稿。修复先核实复现和调用边界，以必要失败回归约束最小实现，验证者给出实际结果；外部发布按用户授权执行。

## 能力和持久化

三种新模板的推荐技能及插件使用当前实际目录匹配，与 Web 模板共用选择和加载流程。不存在的能力只报告缺失，不伪造路径或安装状态；用户已选能力继续参与配置。新模板节点不授予 ComfyUI 工具。

模板标识在创建命令和存储边界统一校验，未知标识拒绝。每次创建有独立项目及空会话、任务和消息；重开恢复用户修改过的定义，不重新套用默认模板。

## 验收边界

通过创建/配置公开命令测试角色、能力缺失、独立状态和持久重开；通过公开条件边 MCP HTTP 测试交接与关联回流；用真实 Electron 表单创建四种模板并验证画布、编辑及重开。执行相关和完整测试、类型检查、构建、双轴审查，合并后从最终 main 重启正式客户端。

本次范围为这四种内置选择；自定义模板保存、模板市场和其他模板不在本次范围。真实模型自主协作的质量须与受控传输和界面证据分开评估。
