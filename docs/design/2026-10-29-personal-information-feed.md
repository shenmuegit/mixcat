# 个人信息流：Codex 目标与结果卡片

状态：2026-10-29 用户修正后的实现规格，替代此前资料管理工作台方案。关联 [Issue #114](https://github.com/shenmuegit/mixcat/issues/114)。

## 用户确认的流程

新建采集 → 与 Codex 沟通目标 → Codex 生成目标与定时任务 → 到点唤醒同一 Codex 会话执行 → 通过一个结果输出工具提交 → 卡片详情展示结果，并可继续沟通目标。

信息流独立于项目；首版只支持文本。每个采集任务有自己的原生 Codex Thread。用户要求旧工作台的内容/任务切换、筛选、搜索、多选调研、手动保存及资料管理入口全部移除。

## 界面

首页使用现有项目页的留白、标题、新建按钮及卡片网格。每张卡片代表一个采集会话，显示名称、简短执行/计划状态、最新结果摘要。空状态只引导新建采集。

新建按[Issue #170](https://github.com/shenmuegit/mixcat/issues/170)增加可选名称和工作目录，以及输入区底栏的原生模型/思考强度选择。未指定时沿用消息暂名和应用内目录。发送第一条消息创建持久会话，Codex 在对话里澄清目标；未发送时可返回，名称、目录、模型与正文草稿保留。

卡片详情按 [Issue #165](https://github.com/shenmuegit/mixcat/issues/165) 调整为 Codex 风格的单列会话：已持久化的完整结果与对话按时间排列，用户消息右对齐，Codex 正文直接阅读，思考和工具活动可展开。内容区独立滚动，底部圆角输入框与发送按钮固定可达；宽窄窗口使用同一结构。实际保存的目标/计划摘要及下一次运行时间通过顶部“目标与计划”查看。移除重复的“继续沟通目标”入口和手动同步原生历史按钮，保留持久历史分页、必要的停止、原生权限回应和失败恢复操作。

首页卡片右键、ContextMenu 或 Shift+F10 打开“删除信息流”。确认后采用既有逻辑删除，关闭后续调度并撤回排队输入；当前运行必须先安全停止并核对，已保存的结果和会话记录仍可追溯。取消和错误不视为删除成功；请求确认丢失时重试使用原操作身份。

用户继续对话即可修改目标、计划或暂停。普通对话文本不当成输出结果；只有工具持久化成功的文本进入结果区。

新建前模型目录从共享账号原生model/list读取，不提前创建采集或Thread；详情读取所属采集的原生目录。模型选择沿用原生默认可见目录的全部分页、名称与标识。底栏选择随消息持久受理并固定到该回合，后来选择不会覆盖已受理的明确配置；最近受理选择也成为后续定时/默认配置。

模型与推理强度弹层按[Issue #181](https://github.com/shenmuegit/mixcat/issues/181)提供的 Codex 设计呈现：上方居中显示当前强度与模型入口，两侧为闪电标识和恢复模型默认强度的重置按钮，下方为原生支持强度的分档滑块。模型选择在同一弹层内展开列表；支持点击、方向键、Home/End、Escape 与点击外部关闭，错误时提供重新读取入口。

所选目录实际作为原生cwd。每个新采集的home和goal.json位于该目录的`.mixcat/feed/<collectionId>/`内，避免覆盖根目录goal.json或混用同目录其他采集。未指定目录的旧采集沿用原应用内位置，不迁移。目录创建后不提供移动入口。

## 实现裁定

以下是工程选择，并非假定 Codex 已有能力：

- 当前本地原生协议的 thread/goal 接口没有定时唤醒能力；继续使用现有 FeedEngine 调度与恢复，不增加第二套调度器。
- Codex 使用自身文件读写能力编辑其会话 workspace 中固定 goal.json；契约为 name、objective、schedule、expectedRevision、requestId。客户端在成功终态验证后原子保存目标与计划。数据库是已接受计划的权威来源。
- 计划沿用 FeedSchedule 的 manual/daily/weekly、时区与 enabled。manual 表示尚无周期安排。Codex 不得承诺不支持的 cron/关机常驻。
- 文件契约受大小、路径、链接、schema、版本和幂等校验约束；派发时记录提案基线，遗留于失败回合的未接受文件不能被后续无关聊天误接受；无效配置不影响旧计划，错误在会话/状态中可见。成功终态恢复亦经过同一应用入口。
- 信息流 MCP 仅保留 save_feed_result 一个输出工具，沿用真实执行身份与持久回执。不同输出请求保存各自正文，不再按来源URL复用旧正文；只有相同请求重试复用回执。去掉查询、上下文读取及独立来源失败工具；所需当前目标/计划随输入上下文提供，来源与失败限制由 Codex 写入结果正文。
- 保留现有单线程串行、未知派发核对、账号/权限、持久队列与草稿保护。不为简化界面删除用户数据库或已保存结果。

## 验收

1. 首页和新建入口符合卡片/对话流程，旧管理工作台控件不再渲染。
2. 两个任务有不同 Thread，各自的后续消息与定时执行继续原 Thread。
3. 对话可持久生成、修改、暂停目标计划；拒绝坏 JSON/过时版本/无效计划时旧配置保持可用并明确报错。
4. 到期执行使用已接受目标，通过唯一输出工具保存，并在对应详情显示完整安全 Markdown。
5. 工具目录恰好一个；重复请求、旧执行或其他任务伪造身份不产生重复/错误归属结果。
6. 导航和迟到响应不丢草稿；键盘和窄窗口可使用；原生请求与必要恢复可达。
7. 完成相关与完整测试、两轴审查、实际客户端闭环验证、PR/合并和最终 main 重启。

运行条件：Mixcat 或托盘运行时执行，完整退出/休眠后的漏跑按现有恢复规则处理。暂不做项目关联。
