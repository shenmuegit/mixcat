# 个人信息流：界面与使用流程

日期：2026-10-29。状态：用户已确认此版布局与流程，作为首版实施规格；实际功能与运行验收尚待实施。首版只支持文本，暂不做项目关联。

## 已确认的方向

- 信息流是应用级个人入口，独立于项目；所有项目关联暂缓。
- 每个采集任务有自己的 Codex 对话，采集结果汇总到同一个信息流。
- 内容用于收集、阅读和整理新闻、个人保存资料及调研成果；采集由 Codex 完成。
- 用户已确认首版只支持文本；信息条目及调研成果以文本/Markdown 阅读，来源链接作为元信息。
- 用户已明确“就按这版布局和流程定稿，继续制定实施计划”。下述布局与流程为本次实施依据；具体工程拆分及默认值见对应实施计划。

## 信息架构

应用侧栏增加“信息流”，进入后有两个主入口：“内容”和“采集任务”。运行记录收纳在采集任务内。

| 页面 | 主要内容与操作 |
|---|---|
| 内容 | 全部／未读／收藏；搜索；采集任务筛选；新建采集、保存资料 |
| 条目阅读器 | 标题、来源、时间、正文或摘录、AI 摘要、备注；收藏、已读、打开来源、追问 |
| 采集任务列表 | 名称、手动或定时、最近运行结果、当前状态；新建采集、立即运行 |
| 采集任务详情 | 对话／结果／运行记录三个页签；任务说明与时间设置入口 |

“全部”按首次收集时间倒序，重复发现不使旧内容重新置顶。条目显示标题、两三行摘要、来源、发布时间或“时间未知”、收集时间及未读标记；不把未知时间推断为当天。

搜索覆盖标题、已保存内容、AI 摘要和用户备注；搜索词与任务筛选叠加。手动保存内容可通过“手动保存”筛选查找；多任务发现的条目可出现在任一对应任务筛选中，但在总流只占一项。

宽窗口以列表和阅读器并排呈现；窄窗口先展示列表，点击进入阅读器，返回恢复筛选、滚动位置和选择。采集任务详情保持单独页面，避免在主信息流堆叠多个聊天窗。

## 流程一：提出采集需求

1. 点击“新建采集”，首先只展示自然语言输入：“你想收集什么？”例如“帮我整理本周国产 AI 视频工具的重要更新，附原始来源”。
2. 默认“一次性，手动运行”；“来源偏好”为可选展开项，可填网站、链接或排除范围。无需先配置订阅。
3. 点击“开始采集”后创建采集任务和独立对话，进入任务详情的“对话”页签，展示实际执行状态。名称可根据需求生成并允许重命名。
4. 已接纳保存的结果逐步出现在“结果”和统一信息流；未完成的候选材料不冒充已保存条目。结束后展示“新增 8 条、重复 3 条、2 个来源失败”等实际结果。
5. 用户可再次手动运行，或进入时间设置启用定时。首次提交前关闭窗口保留草稿，不创建空任务。

采集结果自动进入信息流，不增设逐条人工接纳页。“已接纳”仅指应用已校验并成功保存条目，Codex 声称找到内容或在聊天中贴出链接不等于已保存。界面只按实际保存回执更新数量。普通追问的回答留在对话；明确收集/调研产生的资料及报告进入信息流，用户也可将一条回答显式保存为内容。

原生模型选择、工具与插件能力、登录和权限请求应能在对话中访问。待确认时显示清晰状态和处理入口，不能把原生请求隐藏在后台成功提示里。

## 流程二：阅读与手动整理

打开条目阅读器后标为已读；允许“标为未读”。键盘聚焦列表行或仅展开菜单不算阅读。收藏操作不自动改变已读状态。

阅读器明确分开“来源内容”“AI 摘要”“我的备注”。来源内容标示“全文”“部分内容”或“仅摘录”，附可用的原始链接；AI 摘要标明自动整理，不作为原文展示。备注可独立编辑并自动保存，保存失败保留草稿并提供重试。

“保存文本”支持粘贴文本并选填来源链接。按用户输入保存，缺少链接和发布时间时不编造来源。用户要收集某网页时，可在采集对话里提供 URL，由 Codex 查找并提取可取得的文本；打不开来源时报告失败，不用网页阅读器充当结果。新闻、摘录和调研报告都使用同一文本/Markdown 阅读器。

不同报道保留各自来源；同一资料重复采集只补充发现记录，不重置已读、收藏或备注。内容删除需确认，短时提供撤销；保留删除记录，使后续自动采集不会立即把它收回，恢复入口列出已删除内容。

## 流程三：追问与继续调研

单条追问默认打开发现该条目的采集任务原对话，编辑框带可见的条目引用，用户可补充问题后发送。若有多个来源任务，默认最近发现它的任务，并可切换；手动保存且没有所属对话的条目，发送时创建新的命名调研任务。

多选条目后点击“继续调研”，展示所选资料和可编辑的新任务名称、调研需求；只有点击“发送并开始”才建立新的独立采集／调研任务。成果作为可阅读条目进入信息流，并保留引用来源。返回或取消不产生空任务。

聊天追问只影响当前对话，不自动改写长期采集说明；多来源研究也不把研究目标追加到既有定时任务。修改后续运行目标必须显式进入“编辑采集说明”，保存前说明“从下一次运行起生效”。当前运行继续使用启动时说明。

“采集一次”和定时运行都以当前保存的采集说明为准。运行开始时展示本次采用的说明，并明确带入该次原生 Turn；“这次只看国产工具”等临时追问不能变成后续运行的默认范围。历史仍留在同一 Codex 对话中，说明的版本和本次输入需要可回查；实际模型遵循情况需验收。

任务详情页头显示名称、手动／定时状态和当前执行状态。“对话”用于交流与原生请求；“结果”展示该任务发现的条目；“运行记录”列出时间、触发方式、完成／部分成功／失败／待处理及新增、重复、失败来源，点击可定位对应对话与结果。

## 流程四：定时、停止与恢复

时间设置提供“手动”“每日”“每周”，显示具体时刻、星期、时区、下一次运行和最近结果。启用前展示自然语言确认，例如“每周一 09:00，Asia/Shanghai”。

- “停止本次运行”结束当前执行，保留已接纳结果，不修改定时配置；已有排队输入暂缓，显示“队列待继续”，用户可继续或撤回。队列待继续期间新到期的计划合并等待，不能停止后立即自动重启。显式继续后才恢复派发。
- “暂停定时”阻止未来自动触发，同时撤销尚未开始的定时触发，不影响手动输入；不自动停止当前运行，页面同时显示“本次仍在运行”。恢复定时后重新显示下一次运行，仍尊重“队列待继续”状态。
- 同一任务串行执行。执行中发送新消息时，明确显示“已排队，当前运行结束后处理”，允许撤回待发送消息；手动“立即运行”也显示排队状态，避免重复点击产生多次执行。
- 登录、权限或必要信息缺失时标为“需要你处理”，在任务列表与对话显示入口；尚未处理不应被标记完成。
- 首版仅承诺应用或托盘运行时执行。退出／休眠期间的未触发计划恢复后合并为一次补采，注明实际覆盖时段；执行结果未知时先核对，不能直接当成漏跑重放。

## 页面状态与可访问性

| 状态 | 呈现与下一步 |
|---|---|
| 首次空白 | “还没有收集内容”；提供“新建采集”和“保存资料” |
| 筛选无结果 | 显示当前搜索和筛选，提供“清除筛选”；不误导为没有资料 |
| 采集中／正文加载中 | 保留已有内容，局部显示进度；任务入口可查看执行和停止 |
| 无新增 | 显示重复数量及来源完成情况；有来源失败时仍标“部分成功” |
| 失败／部分成功 | 已保存结果继续可读；展示失败来源与重试入口，重试去重 |
| 需要用户处理 | 显示阻塞原因、打开原生请求的入口；不在信息流插入伪结果 |
| 条目或任务已删除 | 旧引用显示删除状态及可用恢复入口；不显示空白错误页 |
| 删除采集任务 | 先提示停止后续定时，默认保留已有条目和来源归属记录；运行中须先安全停止 |

所有主操作、菜单、页签、筛选及弹层支持键盘，焦点清晰；关闭弹层后回到触发按钮。未读、运行、失败不能只用颜色表达。切换条目、页签、任务和窗口宽度时保留未发送对话及备注草稿；草稿保存失败须可见。

## 可检验的验收条件

1. 用户无需选择项目即可从应用侧栏进入信息流，并看到跨采集任务的统一内容。
2. 仅输入一句需求即可创建一次性任务并开始；两个任务分别拥有可继续的独立对话。
3. 全部／未读／收藏、搜索和任务筛选可组合，清除筛选后恢复完整列表。
4. 打开阅读器标为已读，标为未读和收藏可分别切换；重复采集后状态及备注仍在。
5. 阅读器可区分原始材料、AI 摘要和用户备注，并准确标示部分正文及未知时间。
6. 手动文本可保存并附来源链接；Codex 无法取得网页文本时报告来源失败，不伪造正文。
7. 单条追问携带引用进入所属采集对话；多条研究仅在发送后创建新任务；两者均不改写已有长期说明。
8. 编辑采集说明提示下一次生效；运行中发送消息可见排队并可撤回，任务不并发。
9. 定时设置显示时区与下一次运行；停止本次与暂停未来的效果可分别验证。
10. 部分失败保留已有结果且展示失败来源；原生权限请求可处理；结果未知不被自动重复执行。
11. 删除、撤销、恢复以及后续重复发现行为一致，已删除内容不会立即自动回流。
12. 键盘可完成新建、阅读、收藏、追问和定时设置；窄窗口返回及任务切换不丢滚动位置或草稿。

## 方案取舍与工程边界

曾考虑单一全局个人助手，入口较少，但主题历史、运行归属与定时说明容易混合。用户已选择每个采集任务独立对话；统一信息流承担跨任务浏览，任务详情承载各自交流和运行。

后续构建者决定具体组件、持久化、去重规则、Codex 运行接入与调度机制，并验证退出、休眠和恢复能力；本稿只约束可见行为，不预设实现。具体工程任务、接口与验证边界见[实施计划](../plans/2026-10-29-personal-information-feed-implementation.md)。

独立 builder check 指出的自动入流、临时追问影响后续定时、停止后队列行为已纳入本版流程。交互草图展示新建、阅读、收藏/备注、追问、结果、运行记录和时间设置的主要路径；原生运行、权限请求、删除恢复和排队状态仍以本文约束为准，草图不模拟全部运行边界。

用户已确认文本范围及此版布局和流程。功能关联 [Issue #114](https://github.com/shenmuegit/mixcat/issues/114)；实现与交付按实施计划及仓库流程推进。
