# 个人信息流：Codex 目标与结果卡片

状态：2026-10-29 用户修正后的实现规格，替代此前资料管理工作台方案。关联 [Issue #114](https://github.com/shenmuegit/mixcat/issues/114)。

## 用户确认的流程

新建采集 → 与 Codex 沟通目标 → Codex 生成目标与定时任务 → 到点唤醒同一 Codex 会话执行 → 通过一个结果输出工具提交 → 卡片详情展示结果，并可继续沟通目标。

信息流独立于项目；首版只支持文本。每个采集任务有自己的原生 Codex Thread。用户要求旧工作台的内容/任务切换、筛选、搜索、多选调研、手动保存及资料管理入口全部移除。

## 界面

首页使用现有项目页的留白、标题、新建按钮及卡片网格。信息流侧栏参考画布，在标题右侧提供加号“新建信息流”，空列表及采集详情均可进入新建页面。每张卡片代表一个采集会话，显示名称、简短执行/计划状态、最新结果摘要。空状态只引导新建采集。

新建按[Issue #170](https://github.com/shenmuegit/mixcat/issues/170)增加可选名称和工作目录，以及输入区底栏的原生模型/思考强度选择。未指定时沿用消息暂名和应用内目录。发送第一条消息创建持久会话，Codex 在对话里澄清目标。按 [Issue #313](https://github.com/shenmuegit/mixcat/issues/313)，未发送的名称、目录、模型与正文仅在当前客户端窗口内保留，重新打开后从空表单开始。当前窗口内确认丢失时可重试同一提交，已经接收的对话与排队输入持久保存。

卡片详情按 [Issue #165](https://github.com/shenmuegit/mixcat/issues/165) 调整为 Codex 风格的单列会话：已持久化的完整结果与对话按时间排列，用户消息右对齐，Codex 正文直接阅读，思考和工具活动可展开。内容区独立滚动，底部圆角输入框与发送按钮固定可达；宽窄窗口使用同一结构。实际保存的目标/计划摘要及下一次运行时间通过顶部“目标与计划”查看。移除重复的“继续沟通目标”入口和手动同步原生历史按钮，保留持久历史分页、必要的停止、原生权限回应和失败恢复操作。

聊天内容按 [Issue #207](https://github.com/shenmuegit/mixcat/issues/207) 的 Codex 参考图呈现，沿用当前浅色配色。普通正文和用户气泡不重复显示作者与时间，定时、补跑及系统来源保留标识；思考和工具使用淡色图标摘要行，完整内容可展开。同回合相邻工具记录可折叠为一组，展开明细独立滚动；分组以正文、用户消息、结果和回合为边界，失败与执行中状态可见。

按用户在 [Issue #209](https://github.com/shenmuegit/mixcat/issues/209) 确认的选择，采集详情通过“执行结果”入口在聊天区右侧打开抽屉，选择当前采集的历史成果并阅读完整 Markdown。宽屏两区分别滚动；窄屏抽屉占用内容区，关闭后返回聊天及当前输入。复用已有结果分页、正文和安全 Markdown 显示，提供空态、错误重试、关闭及焦点恢复。

结果工具由 Codex 提交正文等成果字段，标题由客户端在首次保存时生成，格式为“信息流名称_YYYY-MM-DD HH:mm”，使用保存当时名称和本机时间，精确到分钟。既有回执重试沿用首次成果；同一分钟的不同成果用各自记录身份保存。已保存的历史标题继续使用原值。

按 [Issue #241](https://github.com/shenmuegit/mixcat/issues/241)，每条信息流可在详情的 Notion 入口分别授权工作区，选择保存的页面或数据库。授权由原生 Codex 发起，在 Notion 官方页面确认；凭据由原生管理，MCP 配置按信息流身份分别命名并使用其现有独立目录。按 Issue #259、#263 和 #265，最终连接状态为“已链接”和“未链接”，仅原生认证与工作区确认成功时显示不可点击的“已链接”；点击未链接后先显示“正在打开链接”，浏览器打开成功后显示“等待授权”，等待时可重新打开有效授权页，结束后按真实连接状态显示已链接或未链接；保存位置从原生私人/共享页面开始逐层浏览，可返回上级、选择当前页面或子页面及数据库，根目录沿用原生分页，无需输入搜索词。界面显示官方工具返回的工作区，保存位置绑定当前信息流及该工作区。按 Issue #247，Notion 配置卡片保持外框稳定，连接状态、错误及位置选项在内部更新和滚动，标题与关闭入口保持可达。按 Issue #243，入口可打开；待核对运行的原生执行已断开或未恢复时可配置，配置使用不派发业务回合的原生控制会话，不恢复旧业务会话或改写其结论。按 Issue #261，执行期间可读取连接并浏览目录，授权及保存、清除位置继续受原生执行保护；界面显示普通状态提示，执行结束后自动恢复配置。清除位置后后续执行不再向 Notion 发布结果。配置完成的后续原生回合先保存本地成果，再按当前工作区及位置调用 Notion 官方工具；本地工具回执返回实际标题，Notion 成功回执和页面链接保留在原生对话中。写入失败保留本地成果并反馈。

按 Issue #267，选中普通父页面后可在同一保存位置面板内新建空白子页面，名称必填且最多 200 字符。表单沿用现有样式，支持 Enter 创建、Escape 取消，创建时禁用重复提交。原生控制会话校验授权、工作区、父页面类型、采集版本及执行保护后调用官方创建工具。创建成功后在父页面下显示并自动选中新页面，仍需“保存位置”才变更配置。已确认结果通过持久回执复用；远端写入结果未确认时不重发同一请求，提示取消并折叠、重新展开父页面核对后再新建。

按 Issue #269，授权读取完成前显示“检查授权状态”，不将未核实状态显示为未链接；主动打开链接及等待授权的反馈继续保留。私人/共享目录使用树状缩进和原有图标、按钮样式，展开与选择分开，父级和同级始终保留在树中。展开普通页面按需读取子项，数据库仅供选择；目录复用与重新读取按下述 Issue #275 执行。全局“刷新目录”和逐页面包屑导航删除，加载、空分支及失败重试在对应树位置反馈，根列表沿用分页。新建入口要求选中父页面，新页面成功后显示在其下并选中。

按 Issue #271，连接与目录读取优先调用当前原生 Notion 的身份工具，以真实已认证用户和工作区确认连接；成功时直接继续，避免每次额外枚举完整 MCP 服务器状态。身份读取失败才回退原生状态检查，未授权与已认证但工具失败继续按原规则处理。访问原生时仍核对当前工作区，新建/保存继续执行原有版本、工作区和运行保护。

按 Issue #275，当前采集详情内的私人/共享根目录和子分支成功结果短期复用 60 秒，包括空目录；再次展开、切回区域及短时间重开面板不重复查询相同内容。重开面板仍核实原生授权，工作区变化或连接失效即清除目录快照；快照保留范围按 Issue #277 扩展。无近期根目录时，直接用现有根列表接口同时核实身份并读取目录，避免先读取身份再重复核实。目录读取失败保留对应重试；超过有效期后再次访问会读取原生最新内容。新建成功即时更新父分支；派发新建前使父分支快照失效，因此未知或迟到的结果仍可通过折叠重开父分支向原生核对。首次读取未缓存的页面仍需等待 Notion 返回。

按 Issue #277，删除“选择父页面后可新建子页面。”提示。已配置 Notion 的采集进入详情时提前读取目录，面板打开时复用尚未完成的读取；关闭面板不终止所属详情的读取，离开详情后按采集隔离的目录快照仍保留在本次信息流工作区内。已有目录在打开、授权检查和过期刷新时先显示，可选择页面及折叠、展开已读分支；授权状态显示“检查授权状态”，保存和新建等待真实检查及读取完成。根列表在进入、重开或切换区域时检查有效期并后台更新；分支按访问顺序串行读取，不因一次子目录读取而插入额外根查询。失败时清除失效列表并显示重试；连接失效或工作区变化清除旧目录与选择，成功刷新仍存在的路径保留本次选择。新进入的采集才提前读取，不后台授权或轮询全部采集。首次读取尚无快照的目录仍须等待 Notion 返回。

首页卡片及侧栏右键、ContextMenu 或 Shift+F10 打开“编辑信息流”和“删除信息流”。编辑可修改名称与采集目标，保存时校验版本，丢失确认时重试原请求。按 [Issue #313](https://github.com/shenmuegit/mixcat/issues/313)，当前运行须先安全停止并核对，确认后永久删除信息流、本地会话、排队输入、调度以及该信息流独有的结果。文件清理限于应用为该采集创建的独立目录，重启可继续已经确认的文件清理。单独删除结果会移除该条目及其关联的发现与引用。

用户继续对话即可修改目标、计划或暂停。普通对话文本不当成输出结果；只有工具持久化成功的文本进入结果区。

按 [Issue #211](https://github.com/shenmuegit/mixcat/issues/211)，新建和详情输入框 Enter 发送、Ctrl+Enter 换行；输入法组合与选词不触发发送。删除“发送后排队。”提示。执行中发送的消息沿用持久队列，排队聊天消息可点击“插队”，通过 Codex 原生 turn/steer 与 expectedTurnId 加入当前回合，使用当前回合的模型，不新建或停止回合。插队消息使用原生 clientUserMessageId 与历史中的 clientId 关联；回执未知时保留待核对状态，核对原生历史，不自动重发。

信息流使用现有原生 Codex 连接；执行、能力读取与核对无需先在 Mixcat 设置中单独登录，原生错误直接显示。新建前模型目录从共享账号连接的原生model/list读取，不提前创建采集或Thread；详情模型选择通过模型查询范围读取所属采集的原生 model/list，返回模型及推理强度选项；完整能力查询继续提供既有技能和插件目录。模型选择沿用原生默认可见目录的全部分页、名称与标识。底栏选择随消息持久受理并固定到该回合，后来选择不会覆盖已受理的明确配置；最近受理选择也成为后续定时/默认配置。

模型与推理强度弹层按[Issue #181](https://github.com/shenmuegit/mixcat/issues/181)提供的 Codex 设计呈现：上方居中显示当前强度与模型入口，两侧为闪电标识和恢复模型默认强度的重置按钮，下方为原生支持强度的分档滑块。模型选择在同一弹层内展开列表；支持点击、方向键、Home/End、Escape 与点击外部关闭，错误时提供重新读取入口。

所选目录实际作为原生cwd。每个新采集的home和goal.json位于该目录的`.mixcat/feed/<collectionId>/`内，避免覆盖根目录goal.json或混用同目录其他采集。未指定目录的旧采集沿用原应用内位置，不迁移。目录创建后不提供移动入口。

## 实现裁定

以下是工程选择，并非假定 Codex 已有能力：

- 当前本地原生协议的 thread/goal 接口没有定时唤醒能力；继续使用现有 FeedEngine 调度与恢复，不增加第二套调度器。
- Codex 使用自身文件读写能力编辑其会话 workspace 中固定 goal.json；契约为 name、objective、schedule、expectedRevision、requestId。客户端在成功终态验证后原子保存目标与计划。数据库是已接受计划的权威来源。
- 计划沿用 FeedSchedule 的 manual/daily/weekly、时区与 enabled。manual 表示尚无周期安排。Codex 不得承诺不支持的 cron/关机常驻。
- 文件契约受大小、路径、链接、schema、版本和幂等校验约束；派发时记录提案基线，遗留于失败回合的未接受文件不能被后续无关聊天误接受；无效配置不影响旧计划，错误在会话/状态中可见。成功终态恢复亦经过同一应用入口。
- 信息流 MCP 仅保留 save_feed_result 一个输出工具，沿用真实执行身份与持久回执。不同输出请求保存各自正文，不再按来源URL复用旧正文；只有相同请求重试复用回执。去掉查询、上下文读取及独立来源失败工具；所需当前目标/计划随输入上下文提供，来源与失败限制由 Codex 写入结果正文。
- 单线程串行，未知派发须核对，原生权限请求由用户确认，已接收的输入进入持久队列。

## 验收

1. 首页和新建入口符合卡片/对话流程，旧管理工作台控件不再渲染。
2. 两个任务有不同 Thread，各自的后续消息与定时执行继续原 Thread。
3. 对话可持久生成、修改、暂停目标计划；拒绝坏 JSON/过时版本/无效计划时旧配置保持可用并明确报错。
4. 到期执行使用已接受目标，通过唯一输出工具保存，并在对应详情显示完整安全 Markdown。
5. 工具目录恰好一个；重复请求、旧执行或其他任务伪造身份不产生重复/错误归属结果。
6. 当前输入可在界面切换后继续编辑，迟到的确认只消费对应提交的版本。键盘和窄窗口可使用，原生请求与必要恢复可达。
7. 完成相关与完整测试、两轴审查、实际客户端闭环验证、PR/合并和最终 main 重启。

运行条件：Mixcat 或托盘运行时执行，完整退出/休眠后的漏跑按现有恢复规则处理。暂不做项目关联。
