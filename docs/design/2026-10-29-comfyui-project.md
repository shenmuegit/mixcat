# Mixcat 内嵌 ComfyUI 原生画布设计

日期：2026-10-29（UTC+08:00）。状态：实施规划依据；用户确认原生画布内嵌、本地运行环境、厂商自有 Key/API 地址和上游更新，其余采用建议。首批厂商为字节火山方舟、MiniMax、Vidu。

需求追踪：[Issue #155](https://github.com/shenmuegit/mixcat/issues/155)。

实施计划：[10 个任务与供应商协议合同](../plans/2026-10-29-comfyui-project-implementation.md)。

## 1. 目标与用户已确认的范围

新建项目支持 ComfyUI 类型。用户用自然语言描述需求，项目中的 Mixcat Codex 自动搭建、运行和调试 ComfyUI 工作流；用户在 Mixcat 查看生成结果，再提供反馈继续调整。

用户进一步明确：ComfyUI 项目的整个主画布必须集成在 Mixcat 内，提供入口让 Mixcat Codex 编辑该工作流。首版使用本地 ComfyUI 运行环境；用户无需先安装或使用独立 ComfyUI 桌面应用。用户目前没有安装 ComfyUI，运行所需依赖由集成方案处理。

用户随后补充：支持 ComfyUI 使用第三方模型厂商的模型，优先沿用原生支持；支持 ComfyUI 上游仓库更新，方便合并。模型服务可由远端厂商提供，本地运行环境不意味着所有模型都在本机推理。本机 GPU 加速不作为原生画布集成的前置条件或范围确认问题。

最新确认覆盖此前的默认账号方案：用户直接填写各厂商自己的 API Key 与 API 地址。首批支持字节、MiniMax、Vidu；因此图片及异步视频均进入实施范围。Comfy 平台账号/credits 不能代替厂商 BYOK。

主画布中的节点和连线是 ComfyUI 的真实处理节点与数据连接。此前建议的三个 Agent 职责不是用户已确认的设计，也不作为该项目的主画布。

## 2. 当前基础与需要补齐的能力

当前 Mixcat 使用独立原生 Codex 会话承载节点能力，已有模型、技能、插件、MCP、执行历史、暂停和恢复机制。网页工作面板通过 Electron WebContentsView 承载实际页面，浏览器状态保存在项目目录中；目前这些面板绑定会话节点。

当前源码的新建项目入口只有基础及 Web 产品模板。2026-10-29 当前 main 已取消创建时固定目标字段；ComfyUI 新建流程同样不强制用户预先写定完整目标。

ComfyUI 官方本地 MCP 已提供工作流文件、运行、校验、节点和模型查询等能力。它能执行文件，不等于已经连接当前前端内尚未保存的工作流；本需求需要额外提供原生画布编辑连接。

## 3. 接入方式比较与建议

| 方式 | 对本需求的适用性 | 取舍 |
| --- | --- | --- |
| Mixcat 内置受管的官方原生前端，由本地后端同源提供，前端扩展连接 Codex | 推荐；在 Mixcat 主工作区承载原生画布、控件、菜单及扩展 | 固定前后端与桥扩展的兼容版本，管理项目级网页生命周期 |
| 将官方前端源码作为 Mixcat 构建的一部分 | 能使用原生组件，但要长期承担前端构建与后端版本匹配 | 维护面明显更大，当前没有需要修改原生前端的使用需求 |
| 只用 MCP 修改文件并后台运行 | 可辅助工作流研发，但不能满足用户看到的当前画布实时编辑 | 不能作为本需求的完整交付 |

用户已选择“执行与成果管理”，并两次明确原生画布集成在 Mixcat 中。第一项是满足这一要求的技术建议：使用官方完整前端产物，宿主仍是 Mixcat。本地服务是集成运行时，不把打开外部浏览器、另起独立 ComfyUI 窗口或只提供网页链接当成交付。

## 4. 项目入口与原生画布

新建项目选择 ComfyUI 类型和项目目录。首次进入由 Mixcat 检查并准备受管的本地依赖，显示实际准备和连接状态；就绪后主工作区直接呈现集成的 ComfyUI 原生画布。依赖准备属于运行保障，不将用户手动安装一个独立应用作为主要使用流程。

原生节点增删、连接、参数控件、缩放、文件导入、工作流标签页和原生结果预览由原生前端负责。Mixcat 提供可打开和收起的 Codex 会话入口；具体入口位置和面板尺寸交给界面实现，不在本稿固定像素布局。

执行者建议首版为每个 ComfyUI 项目提供一个主要 Codex 助手会话，沿用原生能力配置和历史。用户可以直接描述需求和反馈，人工编辑后的当前画布同样能被助手读取。额外角色与协作图没有已确认使用需求。

切换项目、管理页、窗口大小变化及打开对话面板时，宿主正确隐藏或调整原生网页，保证输入、菜单和弹窗属于当前项目。项目重开后恢复正确的工作流和会话；失败进入可重试的连接状态，不能显示另一个项目的旧画布。

## 5. Codex 编辑同一份工作流

通过 ComfyUI 支持的前端扩展机制，读取当前原生工作流并应用修改；使用原生加载、序列化和运行入口，避免维护第二套图模型。完整根工作流与当前标签页、子图和选区上下文分别传递，不能把当前子图错当成整张工作流。具体扩展安装、传输和工具命名由实现者根据确认的版本决定。

编辑能力至少包含：

1. 读取当前工作流的节点、连接、参数、实际节点类型及现有选区信息。
2. 搭建或修改工作流，并让原生画布实际显示更新后的节点、连线、参数和布局。
3. 校验工作流，提交当前画布对应的运行，读取真实执行状态和失败信息。
4. 获取真实生成文件，关联这次执行的工作流、参数与后续用户反馈。

每次读取返回明确的项目、运行实例、工作流/标签页身份以及版本观察值。写入校验预期身份和版本，避免用户手动修改、切换原生标签页或项目后被旧请求覆盖。冲突时保留用户当前内容，助手重新读取后调整；不将读取时的版本自动更新为新版本。

编辑作为一次明确的变更保存修改前后版本。优先接入原生撤销；若选定版本不能可靠承载 Agent 修改的原生撤销，必须提供已验证的版本恢复入口，并向用户说明实际行为。加载或持久化失败保留可恢复版本，不能仅以工具受理成功声称画布已经修改。

实现中的版本恢复会显式选择待核对编辑。`get_comfy_workflow` 返回待核对请求及其编辑前版本；`restore_comfy_workflow` 以新的 `request_id`、当前 observation、`version_id` 和可选的 `recovery_request_id` 恢复。验证原生读回后，同一事务提交恢复回执，并将原失败编辑及显式关联到它的失败恢复尝试记为 recovered；原编辑不记为成功执行。恢复提交失败时可以重新读取 observation，再用新请求恢复同一原始目标。普通版本恢复不自动解除其他待核对编辑。

此连接只向对应项目的 Codex 提供工作流操作，不能把 ComfyUI 页面变成可调用任意桌面 IPC 的页面。连接身份、来源和响应必须与当前项目及画布实例匹配。

## 6. 描述、生成和反馈循环

用户输入需求后，助手先读取当前画布与本地能力目录，复用已有模板、模型和节点组织工作流。完成编辑后，从同一份原生图生成实际执行数据；不能悄悄运行另一份磁盘草稿。

助手可以依据校验错误、缺失输入和真实运行错误继续修正。依赖安装遵循作者官方流程，并限定在该项目可管理的运行环境；驱动或操作系统调整另行处理。失败必须说明实际原因和已尝试的修正，不能无限重复提交同一个失败任务。

原生校验和执行失败通过持久运行的 `error` 返回给运行详情及 `get_comfy_run`：包含有界的节点、输入、校验类型或异常类型和可识别原因。任意异常正文、输入值与堆栈不公开；无法安全识别的原因明确标注细节未公开，供应商失败另列既有安全错误。

原生 200 受理仍可能携带部分输出分支的 `node_errors`。这些安全诊断保存为独立的 `validationWarning`，在运行详情和 `get_comfy_run` 中提示哪些输出分支未通过校验；有效输出继续执行，运行保持实际 queued/succeeded 等状态。警告在后续成功、迟到受理回执和重开后保留，不充当整个运行失败或受理不明的错误。

运行状态来自 ComfyUI 的实际任务标识、队列、事件和历史。分别显示排队、运行、完成、失败、取消、连接中断和待核实。连接中断后先查询已提交任务的真实状态，不因 Mixcat 重连或 Codex 重试就重复生成。

提交回执只有匹配已分配 prompt 的 200、已验证格式的原生 400 校验失败，以及 403 `Mixcat admission required` 的队列前拒绝能给出确定结论。JSON 5xx、408、409 已消费标识及其他无法证明未受理的响应均保存为 `submission_unknown`，保留原始私有回执与去重记录并查询原 prompt。查到确定队列或执行结果后清除过时的受理不明诊断，必要时替换为实际执行错误。

用户在 Mixcat 内通过原生预览查看输出；对话可以引用某次运行及选定结果反馈。助手以该运行的工作流和参数为基础继续调整，每次新生成形成独立运行记录。运行完成与用户认可结果分别记录。

暂停助手、停止生成、删除队列任务和停止本地服务有各自语义。只能停止属于当前项目的任务，不能把停止助手当成后端任务已经停止。切换项目和重启 Mixcat 时保留工作流、任务标识、历史和恢复依据。

原生后端确认从队列移除指定 prompt 后，运行记录为 `cancelled` 且 `nativeStop: removed`，表示本地队列终态。仅收到运行中断请求或不确定响应不作此判断；远端供应商任务状态独立保留。已确认移除的任务不会因更早的提交回执或查询响应重新变成排队。

## 7. 本地环境与数据目录

执行者建议首次配置准备一个项目可管理的本地 ComfyUI 实例，采用官方发布包或官方文档支持的安装方式。官方前端可通过其发布包提供，也可使用后端支持的 front-end-root 指向已核验的原生前端产物；选择与发布方式以兼容性验证为依据。后端关闭自动打开浏览器，Mixcat 在自己的主工作区承载本地同源的原生页面与 API。

工作流、输入素材、原始生成输出、日志、临时文件、浏览器状态、模型和由本功能创建的运行环境数据，都按用户规则放在所属项目内部。配置 ComfyUI 实际写入位置，不能只在执行后复制输出回来就宣称路径要求已满足。安装器及包管理器的官方安装流程例外按用户全局规则处理。

项目数据目录在执行前核实真实绝对路径和目录联接；不能越过项目根目录或自行回退到 C 盘。配置外部已有运行环境时同样核实实际产物路径；无法满足时明确指出不具备可运行条件。

实例和任务必须有稳定项目归属，不能依赖会被其他项目改动的全局默认 ComfyUI 工作区。具体是每项目独立进程还是经过验证的实例复用，交给实现者在满足隔离、生命周期和资源约束后选择最小方案。

## 8. 原生画布与运行能力验收

先验证真实原生画布在 Mixcat 中的加载、编辑、项目切换和恢复，再验证 Codex 对当前图的操作与执行反馈。原生节点目录、扩展和执行接口由实际 ComfyUI 后端提供；不以静态图片或伪造节点目录替代原生编辑器。

第三方模型工作流可由厂商服务执行推理，Mixcat 内的 ComfyUI 负责图编排与结果展示。仅使用远端 API 节点不要求本机具备推理 GPU；混合工作流中的本地节点仍按实际节点的运行要求验证。

GPU 加速、操作系统升级和显卡专项适配不作为本次画布集成的前置问题。验证报告说明实际采用的运行方式；没有运行的模型或厂商服务不能声称已兼容。

## 9. 可测试验收条件

1. 新建 ComfyUI 类型后进入其原生页面；主画布节点、菜单和交互来自实际 ComfyUI 前端。
2. 本机未安装独立 ComfyUI 应用时，Mixcat 仍可通过受管依赖准备提供该集成功能；准备失败和重试不丢失项目及会话。
3. 项目 Codex 读取当前原生工作流，按自然语言新增节点、连线和参数；修改实际出现在当前画布。
4. 用户手动编辑后，Codex 读取到新内容；旧版本写入、跨项目或跨原生标签页请求不能覆盖当前图。
5. 一次 Agent 修改可通过已验证的原生撤销或版本恢复回到此前内容；应用失败不破坏原工作流。
6. 从当前画布启动实际 ComfyUI 任务，记录任务身份与实际执行图；排队、错误和完成反馈与真实任务一致。
7. 运行完成后在 Mixcat 里查看真实生成文件，反馈关联到正确输出和工作流，后续修改产生可区分的新运行。
8. 缺失模型/节点与实际执行错误可被读取并用于调试；失败、断线和重复请求不会被伪称为成功或盲目重跑。
9. 停止、切换、重开及安全重启能恢复正确图、会话、运行记录和待核实任务，且不会停止其他项目任务。
10. 实际输出、输入、浏览器数据、日志和临时文件均位于所属项目内；越界、C 盘回退或目录联接被明确拒绝。
11. 真实原生页面与桥接边界完成 Electron 交互验收；真实 Codex 工具调用和真实模型生成单独记录。
12. 使用仓库要求的 Issue、相关/完整测试、类型检查、构建、双轴审查、PR、合并和最终客户端重启流程交付；实际模型与运行方式按第 8 节报告。
13. 项目可分别配置字节、MiniMax、Vidu 的自有 Key、API 地址与模型 ID；Comfy 扩展节点使用连接引用，输出原生 STRING/IMAGE/VIDEO，连接上游原生预览/保存节点。各家协议、业务错误、异步任务和参考图能力按实际合同测试；未执行的付费调用如实标识。
14. 可从已记录的上游版本升级前端和后端；升级有独立可审查改动、兼容性回归和可恢复版本，项目图、会话及生成历史继续可读。

## 10. 首版边界与构建者决定

首版为 Mixcat 内嵌的原生画布、项目 Codex 编辑与运行反馈闭环，包含原生第三方模型厂商节点与上游更新。远端模型服务属于本范围；Comfy Cloud 托管整套工作区、多机器调度和通用插件市场属于独立扩展。

由构建者选择最小实现：项目类型与模板字段演进、项目级网页宿主、前端扩展传输、官方 MCP/API 复用比例、版本和回执持久化、目录结构、进程资源管理、工具命名及具体面板布局。选择必须满足上文用户目标和验收边界，不能用后台文件编辑代替当前画布编辑。

## 11. 第三方模型厂商

在 ComfyUI 支持的自定义节点机制中提供小型 Mixcat 扩展。它与连接 Codex 的前端桥放在同一受管扩展包内，提供文本、图片、视频节点，输出原生 STRING、IMAGE、VIDEO，继续使用上游画布与预览/保存能力。此处是 ComfyUI 扩展，不是安装或拼接 Codex 插件。

供应商配置包含名称、协议、API 基址、模型 ID 和凭据引用。原始 Key 只在 Mixcat 可信设置面板输入，以 Electron safeStorage 异步接口加密后保存在所属项目内。原生节点只保存连接 ID 和非敏感参数；主进程中的请求服务解析连接、调用供应商并返回本地资源引用，Python 节点不接收厂商原始 Key。地址和凭据绑定，工作流不能改变目标地址后沿用旧 Key。

| 厂商 | 首版能力 | 必须保留的协议差异 |
| --- | --- | --- |
| 字节火山方舟 | 文字、文生图/参考图编辑、文生视频/图片驱动视频 | 图片引用走 images/generations 的 image 字段；视频是 contents/generations/tasks，不套用 OpenAI 图片编辑接口 |
| MiniMax | 文字、图片生成/人物参考、H3 V2 视频及单列的 Hailuo V1 | 图片解析 base_resp 和部分成功；人物参考不等于通用蒙版编辑；V1/V2 的状态及文件取回协议独立 |
| Vidu | 文生视频、图生视频、参考图生视频 | Authorization 使用 Token；按具体模型校验参考图数量和选项；异步取回结果 |

模型 ID/Endpoint ID 由用户填写或从实际可查询目录选择。API 基址可自定义，但必须符合选定协议；不自动在国内、国际或备用域名间切换凭据。参数能力按所选模型和协议报告，未知能力给出明确错误。

一次执行保存逻辑 run ID、节点调用 ID、连接/凭据修订、输入摘要与厂商任务 ID。创建请求结果不明时进入 submission_unknown，不能盲目追加收费任务。已知任务 ID 后重启继续查询；成功时及时把临时链接内容取回项目。工作流缓存与显式重新生成要区分，每次明确生成具有新的运行标识，恢复同一次运行则复用原回执。

停止等待不代表厂商取消成功。仅使用文档和实际任务状态支持的取消操作；某些 DELETE 在终态会删除远端记录，不能无条件映射为取消。已受理的远端任务继续保留查询和结果恢复入口。

凭据不进入 workflow、prompt、PNG/视频元数据、MCP、聊天、命令回执或日志；厂商错误与签名资源链接按信息需要脱敏。加密保护静态文件，不宣称能隔离同一系统账号下的任意进程或恶意 Python 自定义节点。

调查过的现成节点能提供 BYOK，但部分把 Key 放入 widget 或日志，且没有项目连接引用。因此首版采用独立薄节点与供应商适配，避免为密钥处理修改大型第三方包；额外节点按其真实协议与凭据行为再接入。付费验证只在用户提供连接和明确授权的调用范围内执行。

## 12. 上游更新与适配层

首版建议维护一份兼容版本清单：ComfyUI 后端仓库 URL 与完整提交 SHA、该后端匹配的 comfyui-frontend-package 版本、Python 与已验证的依赖锁、Mixcat 桥扩展版本，以及实际采用的第三方节点提交。官方后端 requirements.txt 本身会固定前端包版本，优先沿用并验证这一组合。

上游来源和发布产物保持可追溯对应关系；原生前端实现由上游维护。当前没有必须修改上游核心的行为，采用版本清单获取官方代码/产物即可；只有实际需要维护源码补丁时再引入独立上游维护分支或子模块。这样常规升级在 Mixcat 中形成清单、依赖锁与少量扩展适配改动，方便审查和合并。

Mixcat 的项目绑定、Codex 编辑工具与生命周期逻辑在自己的代码和独立 ComfyUI 扩展中实现。优先使用官方扩展接口；必须修改上游内部代码时，把必要补丁作为可审查的小范围改动单独维护，并说明原因。

提供维护用的依赖准备、升级验证步骤或脚本。更新通过单独的工作分支/PR进行：选择上游版本，审查变更，更新兼容组合，在项目内的升级验证环境运行原生页面、扩展加载、编辑与撤销、子图和标签页、模型节点、任务状态及恢复测试，再切换受管版本。前端、后端及桥必须按验证过的组合发布；不在用户正在执行工作流时替换运行文件。需求是方便开发者合并上游更新，首版不由此推导出自动定时升级或新的更新管理平台。

升级前记录可恢复的依赖版本与工作流版本；失败恢复整个兼容组合。数据格式若被上游升级，先验证升级和回退的兼容性，不能把版本号回退当成数据已经恢复。新的 Mixcat 版本记录推荐组合，项目实际采用的组合单独记录；切换运行环境时遵循任务完成或安全暂停要求。
