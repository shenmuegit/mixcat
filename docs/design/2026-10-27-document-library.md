# 项目资料文档库

关联 [Issue #21](https://github.com/shenmuegit/mixcat/issues/21)。基线：`ad397b6`。

## 用户明确要求

- 文档承载项目开始后逐步生成的资料，直接以 Markdown 展示。
- 展现形式参考 Obsidian。
- 支持新增、编辑、删除；用户随后取消了上传要求。
- 文档界面没有发送或交给节点入口；待办、Issue 通过引用关联资料并承载后续工作。

本变更延续现有真实文件、共享用户／节点操作、稳定引用和版本冲突契约。以下实施默认值属于执行者的具体选择，不伪称用户逐项指定。

## 方案与默认值

采用真实 Markdown 文件加自动索引。它复用现有文件写入与引用身份，既能展示节点通过管理工具创建的文档，也能发现原生命令写出的资料。仅手工注册不能覆盖后一种来源；另设数据库正文会产生两份内容权威，因此不采用这两种方式。

用户已确认自动发现 `docs/` 内的 `.md`、`.markdown` 文件，递归覆盖设计、计划、报告等子目录；已注册的其他路径继续显示。现有资料首次进入文档库也能发现，不用文件系统创建时间猜测业务生成时间。发现事件记为外部文件，不猜测由哪个节点创建。

打开／切回文档页、手动刷新、节点读取管理上下文以及节点一轮结束时同步目录。使用确定顺序与稳定路径查重；同一文件重复扫描不产生新 ID 或重复记录。归档文件不因扫描自动恢复；回收站文件不参与发现。单次扫描最多检查 5,000 个目录项、1,000 个 Markdown 文件、16 层目录；达到界限和读取失败明确显示，不能报告完整扫描。

排除 `.git`、`.mixcat`、`.runtime`、依赖与构建目录，拒绝符号链接、目录联接、硬链接、路径穿越和项目外文件。现有 UTF-8 及 256 KiB 正文约束继续适用。发现时不改正文。

## 文档工作区

借鉴 Obsidian 的[文件树](https://obsidian.md/help/plugins/file-explorer)、[阅读／编辑视图](https://obsidian.md/help/edit-and-read)、[大纲](https://obsidian.md/help/plugins/outline)和[反向引用](https://obsidian.md/help/plugins/backlinks)，使用 Mixcat 现有的浅色视觉与字体。

- 左侧为真实目录树和搜索，支持文件夹展开／折叠、定位当前文档、新增文档及回收站入口。
- 中间以正文为主，顶部显示文档名称／路径与阅读、编辑、保存等操作。已有文档默认阅读；新文档直接进入编辑。编辑模式保留 Markdown 源文和 `@` 引用选择，阅读模式使用现有安全渲染器。
- 右侧是可收起的大纲和引用栏。大纲来自 Markdown 标题，点击跳转到正文；引用与反向引用沿用现有管理对象身份和消息／评论定位。
- 文档没有负责人、优先级、业务完成状态或发送控件。待办和 Issue 的现有操作继续使用同一管理服务。
- 切换文档／项目视图保留逐文档草稿；外部修改不覆盖脏草稿，保存仍要求当前修订和文件哈希。保存成功后才显示已保存。

首版采用阅读和源码编辑切换，不实现 Obsidian 插件、云同步、图谱、多窗口或富文本 Live Preview。既有标准 Markdown `mixcat://` 引用继续使用，不引入第二套 wiki-link 身份。

## 新增、删除与恢复

新增保存真实 `.md` 文件，默认位于 `docs/`，可使用项目内允许的路径。已有目录按文件路径呈现；名称／路径变更复用现有移动操作，保持 ID。

删除是文档专属操作，不复用 Todo／Issue 的归档语义。用户确认中看到文档名称、真实相对路径及引用提示。受管操作校验修订与当前正文哈希，然后将文件移到项目内 `.mixcat` 回收区域，记录删除状态、作者及时间。文档 ID、修改历史和引用身份保留；普通搜索／新引用候选不包含已删除文档，已有引用明确标记已删除。

回收站可阅读并恢复文档。恢复沿用原 ID；原路径被占用时拒绝覆盖，可显式选择其他项目内路径。删除和恢复复用文件／状态协调日志，重启能恢复一次已受理操作；中途外部改动仍停止恢复，保留可处理的记录。请求重放不会重复删除或创建身份。

外部直接删文件仍显示文件缺失，不把它冒认为用户在客户端删除。外部移动不凭同名文件猜测身份；必须保留显式重新关联的可行路径，自动发现不得把它堵死。实施者可对“旧路径缺失且新文件内容相同”的候选暂停自动注册并提示重新关联，不能自动合并身份。

已删除文档不能成为新的显式工作关联或新的核对材料；既有条件边交接继承原关联时保留历史引用，不因资料后来删除而阻断交接。已有执行和固定核对快照保留历史事实。当前材料检查应识别删除，不能因回收副本仍存在而认为原材料继续有效。

## 验收

1. 原生方式写出资料后，无手工注册也能在文件树、搜索和 `@` 候选看到；重复刷新／重启不重复。
2. 边界目录、链接、无法读取、大文件及扫描上限得到准确反馈；项目外数据不被访问。
3. 新增、编辑、外部冲突、目录导航、大纲、引用与反链，以及切换时的草稿均通过实际 Electron 操作。
4. 删除／恢复使用真实文件，旧引用状态清晰，冲突不覆盖；注入文件动作完成但 SQLite 提交失败，重启恢复正确。
5. 文档页无上传及节点发送入口，Todo／Issue 的引用与发送、工作流全高布局及旧回归继续通过。
6. 按仓库流程完成 Issue、两轴审查、测试、PR、合并、正式客户端构建和重启。
