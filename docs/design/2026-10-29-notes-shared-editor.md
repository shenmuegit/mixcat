# 独立笔记与共享文档阅读编辑

关联 Issue #108。用户已确认按本方案推进；基线 `e2c5c4c4d78f5e409a6fd8cf838b7a099fccfca0`。

## 用户确认的目标

新增与项目并列的笔记功能，迁入 Grove 的笔记功能和交互体验，包含脑图组织与笔记关联。项目内文档继续以项目文件为内容来源；笔记与项目文档调用同一套阅读、编辑组件，仅来源和所属业务不同。不迁移 Grove 旧数据。

## 方案选择

采用 Grove 受控阅读编辑组件作为共同实现起点，在 Mixcat 内形成单一正文阅读编辑实现，再由两个来源接入。另一条路线是在现有 Mixcat 编辑器上逐项重做 Grove 交互，会重复实现已存在的表格、粘贴和预览行为；复制两份编辑器又不满足共享代码的要求。用户认可共用 Grove 风格阅读编辑、分别处理数据来源的方案。

## 结构与实施默认值

- 笔记入口可在无项目时使用。笔记数据归工作台根目录，存放在 `.mixcat/notes/`；项目文档继续写所属项目文件。这是执行者选择，不引入全局系统目录。
- 笔记使用稳定 ID、标题、Markdown 正文、父笔记、同级顺序、关联 ID、创建/更新时间和回收状态。使用现有 Node SQLite 能力持久化笔记与操作回执，单次关系或层级变更原子完成。
- 脑图支持根/子/同级笔记、新增、打开、折叠、展开、平移缩放、调整父级和同级顺序、拖动组织、搜索定位和返回原视口。脑图层级不以文件路径推导。父级循环、自关联和不存在目标由后台拒绝。
- 笔记关系为无向关联；任一端都能看到和打开另一端。移除关系同时对双方生效。删除进入回收站；删除子树前明确影响，恢复保持身份和关系，已删除目标不作为新增关联候选。
- 共享组件处理标题/正文、Markdown 阅读与 CodeMirror 实时预览、表格编辑、富文本粘贴、图片媒体呈现和阅读编辑位置连续性。组件不读取数据库、不知道项目目录。
- 上层管理加载、保存、版本检查、草稿、资源存取、关联及导航。共享组件通过回调使用来源的补全、链接和媒体能力。项目 `@` 搜索与 `mixcat://` 引用继续按项目上下文工作。
- 每份内容以 `note:<id>` 或 `project:<projectId>:<documentId>` 隔离编辑状态；切换时不串正文、撤销或异步图片插入。保存失败保留草稿；切回阅读须保存成功。未保存草稿离开应用前有现有保护提示。
- 图片和媒体落到所属来源目录，解析相对路径时检查实际目录范围、祖先链接和文件类型；危险 URL/原始 HTML 不执行。远程资源和可支持媒体类型按共享渲染安全策略处理。
- 项目导入媒体保存在项目 `assets/mixcat/`，正文使用来源内稳定的 `mixcat-asset:<内容哈希>.<扩展名>` 标识；文件跨目录移动和首次保存路径调整不改变导入资源的位置。现有普通相对图片路径按当前文档目录解析。笔记媒体保存在笔记根目录的 `assets/`。
- 项目文档文件树、自动发现、真实文件、稳定引用、保存冲突、删除恢复和移动重关联接入共享编辑器。脑图与笔记关联属于独立笔记模块。

## 边界

Grove 的旧数据导入、账号云同步、社区、想法/技能模块和 AI 分析不是本次功能。工作流派发和人工核对不因笔记模块改变。跨项目资料自动共享不由笔记入口推导。

## 验收与验证边界

1. 公开笔记命令验证无项目创建、编辑、重开持久化、同级排序、层级调整、循环拒绝、双向关联、删除恢复和版本冲突/请求重放。
2. 实际 Electron 验证脑图创建/折叠/移动/关联/搜索/打开返回，笔记和项目文档共同编辑器的阅读、输入、表格、富文本粘贴、媒体、保存和切换。
3. 两种内容来源之间草稿、撤销历史、资源路径和引用上下文隔离。外部修改项目文件后保存拒绝覆盖，草稿可继续处理。
4. 相关测试、类型检查、构建、最终完整测试和 Standards/Spec 并行审查。按 Issue→PR→CI→合并交付，最终 main 构建后安全重启实际客户端，核对进程与 desktop ready 日志。
