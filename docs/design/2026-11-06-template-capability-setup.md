# 创建模板项目时准备能力

Issue：[193](https://github.com/shenmuegit/mixcat/issues/193)。日期：2026-11-06。

用户已确认：仅新建项目并选择模板时安装该模板对应的插件和 skills；发现 Codex 已有相关能力时先提示覆盖或跳过，默认跳过。覆盖必须来自用户的明确选择。

## 方案与范围

复用现有项目创建回执、项目独立 Codex、原生能力目录和节点配置。首次启动全量安装会安装用户未选择模板的依赖，用户已明确排除；仅提示手工安装不能解决新电脑问题。采用创建后的按模板准备：项目先安全建立，再检查该模板能力、处理已有能力选择、安装缺失项并回读配置。

安装单元按作者发布的原生插件或独立 skill 去重。插件携带的 skills 随完整插件安装，节点只选择本角色所需项。调研/内容所需 ECC、Superpowers、planning-with-files；修复额外需要 Ponytail 和 GitNexus；Web 还需要独立 Impeccable skill。实际集合从模板的角色推荐派生，不能把其他模板的包一起安装。

插件只从作者原始市场和官方 Codex 原生安装接口安装，不复制宿主缓存、不拼装市场或 manifest。Impeccable 是作者为 Codex 提供的独立 skill，使用官方 impeccable CLI 的 project/Codex 安装模式；不将原生插件改装成独立 skills/hooks。未支持、网络失败和需要额外授权的项如实显示。

## 已有能力与覆盖决定

检查当前项目目录和本机 Codex 中的相关安装副本；已有项按安装单元展示来源和可获知版本，默认跳过。对话框明确安装目标是当前项目的独立 Codex/skill 目录，覆盖不会暗改其他 Codex 环境。跳过不删除、不替换已有能力；当前项目已可见的能力可以继续配置，只有本机副本而项目不可见的项显示为跳过且当前项目未就绪。

所有覆盖选择必须绑定最近一次目录观察。安装前重新检查；目录内容或版本变化时回到选择步骤，不应用旧决定。同一项目不能并发准备。运行中或待处理工作必须保护，不能在模型工作期间替换其能力。

## 交互与恢复

新建后显示“准备模板能力”，包含当前模板、逐项状态和已有项的覆盖/跳过选择。没有已有项时直接准备缺失项；有已有项时先等待用户选择。安装中显示实际进度；完成后回读原生插件/skills 目录并配置节点，不能将安装成功等同于已加载或已信任。

逐项结果区分已就绪、已安装、已跳过、失败、需授权或不支持。保留已建项目；重试重新检查实际状态，不盲目覆盖。关闭/重开客户端不自动重新安装，未完成项提供用户主动继续入口。恢复旧目录不触发新建安装流程。

hooks 信任与外部账号授权保留官方审核流程，不写 trusted_hash、不替用户批准，不启动模型或付费任务。独立 skill 的安装只使用作者支持的参数，写入所属项目；插件与项目缓存、日志和验证数据遵守项目路径规则。

Impeccable 官方安装器会寻找上层 Git 仓库根目录。当前项目若位于其他仓库的子目录，停止此项并说明可选用仓库根目录或跳过，避免向项目外写入。原生同名插件跨市场覆盖时，先确认新插件安装成功，再通过官方管理卸载当前项目内的旧标识；不能确认归属的副本交由用户通过官方管理处理。

## 验收

公开项目命令及原生安装协议边界验证模板集合、已有项、覆盖/跳过、过期决定、并发、失败重试与重开；实际 Electron 验证完整新建和选择交互，production IPC 验证新增回执字段。隔离的干净 Codex 环境验证真实官方安装和能力发现，不伪称已完成 hooks 信任、外部账号或真实模型协作。完成完整测试、类型检查、构建、两路审查、PR/合并和最终 main 实际客户端重启。
