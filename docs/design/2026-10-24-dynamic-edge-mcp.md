# Mixcat 动态条件边 MCP

日期：2026-10-24。用户已确认本方案并授权实施。本文件覆盖早期协作设计中“允许无连线发送”和固定 `send_message`／`handoff` 对外入口的规则。

## 目标与范围

条件边是节点间传递工具的唯一配置来源。每个节点只获得自己出边对应的 MCP 工具，工具描述使用已有边 ID、方向和条件文本。程序不根据产品经理、设计、开发、测试等角色编写不同的业务工具，也不新增一套协作动作配置。

工作流画布只绘制当前配置的条件边，不将历史消息或旧交接额外画成连接线。旧的无边通信和已有条件边上的消息记录均保留在节点会话与项目会话历史中，不删除原始事实，也不因历史消息生成新的配置关系。

画板的运行提示取自受理时保存的 edgeSnapshot 与接收任务：公开消息摘要携带该快照，接收任务通过 incomingMessageId（兼容原始 target_task_id）关联投递及重试。只有边编号、版本和两端节点仍与当前配置一致时显示工作/等待提示，不能从相邻节点正在运行推断条件已使用。同一边的在途任务优先展示实际工作，再展示等待状态；完成/取消/失败不继续移动。该标识不改消息事实、调度或边配置，用户直接输入及无边快照的旧消息不会点亮某条条件边。

工具生成时确定路径；Agent 根据条件描述选择调用，Mixcat 随后保存并投递，不再判断条件是否满足或重复核对路径。Codex 原生工具、插件、skill、会话历史与用户对任意节点的直接输入保留。

## 工具生成与调用

- `WorkflowEngine` 根据项目中已经保存的条件边，为节点身份绑定出边快照。保存、修改、删除边以及删除关联节点后，一并更新这些绑定；未提交成功的编辑不会改变工具。
- 一条出边生成一个工具。同一对节点之间的不同条件边分别保留；入边不会自动成为反向发送工具。
- 工具名由边 ID 和绑定目标组成的 JSON 数组计算 SHA-256，取前 32 个十六进制字符，前缀为 `edge_`。这样允许现有最长 100 字符的边 ID，又保持原生工具名长度稳定。节点改名和条件编辑保持工具标识；修改目标则替换为另一个工具，避免正在执行的模型用旧工具悄悄发给新目标。
- 工具的 `title` 表示来源和目标，`description` 包含现有条件文本。Agent 提供 `request_id`、自由 JSON `content`、`reason`，可附带原有附件和 `reply_to`。不暴露可填写的目标节点或边版本参数。
- MCP 工具处理函数直接绑定目标和边快照，复用现有持久消息、附件、FIFO、回执与原始历史。调用时不再查询工作流以重选路径或校验边版本。
- 原有 `handoff`／`send_message` 不再出现在 MCP 工具目录，手工猜测这些名称也不能调用。已有消息、交接记录及内部恢复逻辑保留，不修改历史数据。
- 条件边本身提供其对应的发送能力，不另要求勾选旧的发送工具。节点配置只列出其余可选工具。

身份识别、参数格式、来源执行归属、存储错误、附件保护和重复请求处理沿用现有实现。人工核对和暂停仍作用于队列派发：暂停或等待核对的目标可以保存来信，不因收到消息被自动启用。

## 变动与在途调用

工作流编辑成功后，MCP 网关的目录随之更新。已经进入处理函数的调用使用当时绑定的目标和条件快照，即使准备附件期间边被修改，也不将其悄悄改投其他节点。

已受理的同一请求重放返回原回执，不因后来修改目标或条件而改变原始发送。已删除的工具不接受新调用；原消息可以通过现有 `get_delivery` 恢复回执。不同业务内容复用同一请求编号仍报冲突。

不增加自然语言条件解释器、二次路由审批、第二个选择 Agent 或新的消息格式。

## 原生会话的目录刷新

实测的 `codex-cli 0.164.0-alpha.11.1` 会在已加载 Thread 中保留旧工具目录。单独重载配置或直接恢复已加载会话，不能据此认定模型已经看见新工具。

当前实现记录各 Thread 上一次使用的身份与条件边快照。目录变化后，在该节点下一轮派发之前调用 `thread/unsubscribe`，随后以原 Thread ID 执行已有 `thread/resume`，再开始新 Turn。没有变化时不释放连接，也不影响其他节点。该方式在当前原生版本中已通过实际模型请求体核对。

正在执行的轮次不强制中断，也不自动增加新的用户输入。新增、删除工具对模型的可见性在下一轮生效；原 Thread 和其上下文继续保留。Agent 在当前轮新建联系后，使用新工具同样遵循这一边界。

该刷新行为需要在升级 Codex 时复验；不从协议存在相关方法推断所有原生版本均有相同缓存行为。

## 验证

定向回归覆盖节点隔离、无出边、同目标多条件、条件更新与删除、猜测旧入口、来源元数据、自由内容、附件准备期间修改边、暂停队列、原回执重放，以及同一 Thread 的目录刷新。

`scripts/verify-dynamic-edge-native.ts` 使用真实 Codex app-server 和本地受控 Responses SSE 服务，检查两个节点的工具隔离、增删工具实际进入模型请求、原生工具保留和原 Thread 历史连续性；它不调用真实模型服务，也不冒充真实模型的选路验收。

实现与验证进度见[实施记录](../plans/2026-10-24-dynamic-edge-mcp-implementation.md)。
