# 统一 Issue

2026-10-29。用户已认可统一工作项，并明确删除待办入口、统一到 Issue。关联 [Issue #107](https://github.com/shenmuegit/mixcat/issues/107)。

## 目标与选择

同一件事从记录、讨论、拆解、交给节点到验收只维护一条工作记录。采用统一 Issue：普通任务、缺陷、需求、改进是类型，待处理、进行中、阻塞、已完成、已取消是状态。新建默认普通任务。导航只提供工作流、Issue、文档。

只合并入口仍会留下两套能力；Issue 管目标、Todo 管行动则会增加小任务的重复登记。用户选择统一对象能力。树形父子关系表示工作拆解，普通引用表示相关材料；一次执行仍只是一次尝试，执行完成不自动完成 Issue。

## 可观察行为

- 新旧工作项在同一个 Issue 树表中展示，提供类型、进度、负责人、优先级、更新时间及搜索。搜索匹配子项时显示祖先路径；折叠、排序、拖拽及等价操作继续可用。
- 所有非文档工作项都能拥有子项、评论、引用和主工作执行关联，旧待办可与新 Issue 混合组成树。
- 完成、取消、关闭和重开要求处理说明。历史 closed 继续显示已关闭，不能推定为已完成。只有 done 计为交付完成；取消和历史关闭的叶子从当前交付分母排除。父项存在未结束子项时不能完成或取消，重开子项须重开结束的祖先。
- 创建子项、移动、归档和恢复沿用循环防护、版本冲突及完整子树规则。新状态修改不得悄悄重开祖先。

## 兼容策略（实施选择）

保留旧 todo 的存储 kind、ID、T- 编号与 URI，新建统一使用 issue/I-。旧 todo 是历史身份别名，产品中没有单独入口或独占能力。查询 issue 同时包含历史 todo；旧链接导航到 Issue。历史消息、幂等回执和核对包不进行批量改写。

旧 todo.issueType 是未使用的 bug 占位，统一按普通任务解释。可选 legacyTodoType 只记录旧对象后来明确选择的类型，issueTypeOf 统一读取类型；新 Issue 直接使用 issueType。材料序列化在旧 todo 未变更类型或仍为普通任务时保持原值，真正改变类型后纳入核对内容，避免升级使批准失效或类别变更漏检。

新增 primary_issue_id 作为规范主关联字段，兼容 primary_todo_id。两个字段冲突时拒绝；主关联只能指向本项目非文档对象。旧关联按实际对象类型补引用。新旧字段经节点输入、条件边继承和回复传递。

本方案复用已有存储和接口，不增加依赖；文档、工作流调度、人工核对的独立职责继续按现有契约执行。

## 验收

命令边界验证混合树、类型、状态、进度、评论、重启持久化与冲突；MCP 边界验证新旧主关联、继承/回复/幂等、旧材料兼容及实际变化失效；渲染和 Electron 验证三入口、旧引用、树表、草稿、评论、派发和窄窗口。完整测试、类型检查、构建与两轴审查完成后按仓库流程合并，并在最终 main 正常重启实际客户端。
